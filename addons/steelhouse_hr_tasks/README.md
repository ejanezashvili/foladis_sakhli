# steelhouse_hr_tasks - კადრების პროცესები

კომპანიის სამი HR პროცესი (2026-11-25) დავალებებად, `steelhouse_task_flow`-ზე დაშენებით (მისი ფაილები არ იცვლება, D-10).

## რას აკეთებს
- აპი **„კადრები“**: „მოთხოვნები“ (დაფა პროცესის სტატუსით), „ახალი მოთხოვნა“ (ვაკანსიის განთავსება / ახალი
  თანამშრომლის აყვანა / თანამშრომლის გათავისუფლება), „პარამეტრები“ (HR).
- პროცესის სტატუსი `sh_hr_state`: ახალი → დირექტორთან → დამტკიცებულია → (გადახდაში - ვაკანსია) → დასრულებულია /
  უარყოფილია. დავალება ამავდროულად დაფის საერთო სვეტებშია (ახალი / მიმდინარე / დასრულებული / გაუქმებული) -
  რეპორტები და „მთავარი“ ჩვეულებრივ ითვლის.
- სავალდებულო ველები სახეობის მიხედვით (`REQUIRED`, `models/task_hr_process.py`); ცარიელით „დირექტორს გაგზავნა“ არ
  ხერხდება, ფორმაზე - „შესავსებია: ...“. დამტკიცებამდე სვეტებში გადატანა იბლოკება.
- „დირექტორს გაგზავნა“ - HR მენეჯერი (+ აქტივობა დირექტორს); „დამტკიცება“ / „უარყოფა“ (მიზეზით) - მხოლოდ დირექტორი.
- დამტკიცებისას (აყვანა / გათავისუფლება): იურიდიული პირის ბუღალტერი და იურისტი ხედავენ დავალებას („დამატებით
  ხედავენ“), იქმნება ქვედავალებები - აყვანა: იურისტი (დოკუმენტები), დროის აღრიცხვა, ბუღალტერი (RS.ge);
  გათავისუფლება (მონიშნულის მიხედვით): იურისტი, ბუღალტერი, შიდა უსაფრთხოება.
- მოთხოვნას ქმნის სისტემა დაფაზე „კადრები“ (ავტორი - „მომთხოვნი“, ხედავს თავის მოთხოვნას; დაფა მას ხილვადობის
  წესით არ უჩანს). ნომერი `HR-0001`.

## პარამეტრები („კადრები → პარამეტრები“, HR / ადმინი) - 19.0.1.10.0-დან ყველაფერს HR წინასწარ წერს
- **ადამიანები:** HR მენეჯერი (შემსრულებელი + შემმოწმებელი), დირექტორი; იურიდიული პირები - სახელი, ორგანიზაციის
  კოდი, ბუღალტერი, იურისტი (`steelhouse.legal.entity`).
- **ვაკანსია / აყვანა / გათავისუფლება** (ჩანართები): **სავალდებულო ველები** (`steelhouse.hr.field` - პროცესის ველების
  სია, ივსება მოდულით; HR მონიშნავს) და **ქვედავალებები** (`steelhouse.hr.subtask.rule`: სახელი, ვის ეწერება -
  იურიდიული პირის იურისტი / ბუღალტერი / არჩეული ადამიანები, „შეიძლება გამოტოვება“). მოთხოვნაზე HR მონიშნავს
  „არ არის საჭირო“ - ეს ქვედავალება არ შეიქმნება. პირველი შევსება - კლიენტის დოკუმენტებით (`_sh_defaults`).
- **დამატებითი ველები** (19.0.1.15.0): HR ჩანართში თავად ქმნის ველს (სახელი, ტიპი: ტექსტი / გრძელი ტექსტი / თარიღი /
  რიცხვი / კი-არა, სავალდებულო) - `steelhouse.hr.extra.field`; მოთხოვნის ფორმაზე ჩანს Odoo-ს „თვისებად“
  (`sh_hr_properties`, განმარტება `steelhouse.hr.kind.properties_definition`, ერთი ჩანაწერი თითო პროცესზე, მხოლოდ
  მოდული წერს). მნიშვნელობა მოთხოვნაზეა - ხედავენ მხოლოდ მისი მონაწილეები. სავალდებულოს გარეშე არ ინახება.
- ქვედავალებები მხოლოდ **არჩეულ ადამიანებს** ეწერება (19.0.1.14.0); იურიდიული პირი - სახელი + ორგანიზაციის კოდი.
- სავალდებულო ველების შემოწმება მოდულის დაყენება / განახლებისას გამორთულია (ძველი მოთხოვნები არ ამოწმდება).

## დაყენება / განახლება
