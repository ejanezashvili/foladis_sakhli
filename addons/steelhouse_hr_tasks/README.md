# steelhouse_hr_tasks - კადრების პროცესები

კომპანიის სამი HR პროცესი (2026-11-25) დავალებებად, `steelhouse_task_flow`-ზე დაშენებით (მისი ფაილები არ იცვლება, D-10).

## რას აკეთებს
- აპი **„კადრები“**: „მოთხოვნები“ (დაფა პროცესის სტატუსით), „ახალი მოთხოვნა“ (ვაკანსიის განთავსება / ახალი
  თანამშრომლის აყვანა / თანამშრომლის გათავისუფლება), „პარამეტრები“ (HR).
- პროცესის სტატუსი `sh_hr_state`: ახალი → დირექტორთან → დამტკიცებულია → (გადახდაში - ვაკანსია) → დასრულებულია /
  უარყოფილია. დავალება ამავდროულად დაფის საერთო სვეტებშია (ახალი / მიმდინარე / დასრულებული / გაუქმებული) -
  რეპორტები და „მთავარი“ ჩვეულებრივ ითვლის.
- სავალდებულო ველები პროცესის მიხედვით - პარამეტრებიდან (`<kind>_field_ids`); ცარიელით მოთხოვნა არ ინახება და „დირექტორს გაგზავნა“ არ
  ხერხდება, ფორმაზე - „შესავსებია: ...“. დამტკიცებამდე სვეტებში გადატანა იბლოკება.
- „დირექტორს გაგზავნა“ - HR მენეჯერი (+ აქტივობა დირექტორს); „დამტკიცება“ / „უარყოფა“ (მიზეზით) - მხოლოდ დირექტორი.
- დამტკიცებისას იქმნება ქვედავალებები პარამეტრების წესებით (გარდა მოთხოვნაზე „არ არის საჭირო“-თი მონიშნულისა);
  მათი ადამიანები მოთხოვნას ხედავენ („დამატებით ხედავენ“) და მიმდევრები ხდებიან.
- მოთხოვნას ქმნის სისტემა დაფაზე „კადრები“ (ავტორი - „მომთხოვნი“, ხედავს თავის მოთხოვნას; დაფა მას ხილვადობის
  წესით არ უჩანს). ნომერი `HR-0001`.

## პარამეტრები („კადრები → პარამეტრები“, HR / ადმინი) - 19.0.1.10.0-დან ყველაფერს HR წინასწარ წერს
- **ადამიანები:** HR მენეჯერი (შემსრულებელი + შემმოწმებელი), დირექტორი; იურიდიული პირები - სახელი, ორგანიზაციის
  კოდი (`steelhouse.legal.entity`).
- **შაბლონები** (19.0.1.22.0-25.0, D-14): ჩანართების ერთი ხაზი - „ადამიანები“ + თითო შაბლონი (სამი ჩაშენებული +
  HR-ის შექმნილი, `steelhouse.hr.kind`) + „+ ახალი შაბლონი“; ჩანართზე - სავალდებულო ველები და ქვედავალებები, ქვემოთ
  „სახელი / არქივი / წაშლა“ (შაბლონის ფორმა). შენახვისას მენიუ თავად ახლდება (F5 არ სჭირდება). ახალი შაბლონი - „ახალი მოთხოვნა → + ახალი შაბლონი“ (HR): სახელი,
  ველები („+ ახალი ველი“), სავალდებულოები, ქვედავალებები; შენახვისას მოდული ქმნის მენიუს პუნქტს „ახალი მოთხოვნაში“.
  გზა იგივეა (HR → დირექტორი → ქვედავალებები; „გადახდაში“ მხოლოდ ვაკანსიაზე). მოთხოვნიანი შაბლონი არ იშლება -
  არქივდება (მენიუდან ქრება).
- **თითო შაბლონის ფორმა** (ადრე ჩანართები ვაკანსია / აყვანა / გათავისუფლება): **სავალდებულო ველები** (`steelhouse.hr.field` - პროცესის ველების
  სია, ივსება მოდულით; HR მონიშნავს) და **ქვედავალებები** (`steelhouse.hr.subtask.rule`: სახელი, ვის ეწერება -
  არჩეული ადამიანები, „შეიძლება გამოტოვება“). მოთხოვნაზე HR მონიშნავს
  „არ არის საჭირო“ - ეს ქვედავალება არ შეიქმნება. პირველი შევსება - კლიენტის დოკუმენტებით (`_sh_defaults`).
- **ახალი ველი** (19.0.1.17.0, 21.0): „სავალდებულო ველების“ ჩამონათვალში „+ ახალი ველი“ (ყოველთვის ჩანს, „მეტის ძიება...“-ს ზემოთ) - სახელი + ტიპი (ტექსტი /
  გრძელი ტექსტი / თარიღი / რიცხვი / კი-არა); ველი იმავე სიაშია (`steelhouse.hr.field`, `pname`) და მაშინვე
  სავალდებულოა. მოთხოვნის ფორმაზე ჩანს Odoo-ს „თვისებად“ (`sh_hr_properties`, განმარტება
  `steelhouse.hr.kind.properties_definition`, მხოლოდ მოდული წერს), მნიშვნელობა მოთხოვნაზეა - ხედავენ მისი
  მონაწილეები. შექმნილი ველი იშლება „ძიება“ ფანჯრიდან (სანაგვე ღილაკი, 19.0.1.20.0 - ცალკე სია „შექმნილი
  ველები“ მოხსნილია); ჩაშენებული არ იშლება. ფორმაზე სხვა ველებივით ჩანს (ნაცრისფერი ყუთი, 19.0.1.19.0); „*“
  შექმნილ ველზე ნაცრისფერია (სახელის ნაწილია).
- ქვედავალებები მხოლოდ **არჩეულ ადამიანებს** ეწერება (19.0.1.14.0); იურიდიული პირი - სახელი + ორგანიზაციის კოდი.
- სავალდებულო ველების შემოწმება მოდულის დაყენება / განახლებისას გამორთულია (ძველი მოთხოვნები არ ამოწმდება).

## დაყენება / განახლება
ახალი ველები → `odoo -u steelhouse_hr_tasks --stop-after-init` (სერვისი გაჩერებული), ბაზის ასლი ჯერ.

  შემმოწმებლის / მიზეზის წესები - მათი შეცვლა ამ მოდულზეც აისახება.
