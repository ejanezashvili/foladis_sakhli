# ფოლადის სახლი — დავალებების მართვის სისტემა

Odoo 19 Community-ზე (Project აპლიკაცია) აწყობილი დავალებების მართვის სისტემა.

- `Docs/ფუნქციონალი (2).docx` — კლიენტის მოთხოვნები
- `Docs/გეგმა.md` — დანერგვის გეგმა ეტაპებად და მოთხოვნების რუკა
- `addons/` — საკუთარი და OCA მოდულები (მომზადების პროცესშია)

პრინციპი: ჯერ Odoo-ს ჩაშენებული ფუნქციონალი, შემდეგ OCA მოდულები, საკუთარი კოდი — მხოლოდ ხარვეზებისთვის.

## მოდული `steelhouse_project` (ჯერ არ არის დაყენებული)

დაწერილია, სერვერზე არ არის დაყენებული — ელოდება დამტკიცებას (დავალებების ეტაპი).

დამოკიდებულება: მხოლოდ `project`. დაყენება: საქაღალდე `addons/` დაემატოს Odoo-ს `addons_path`-ში → Apps → Update Apps List → „Steelhouse Project“ → Install.

რას ამატებს:
- **სტადიები** და პროექტი „ოპერატიული დავალებები“: ახალი → მიღებული → მიმდინარე → შეჩერებული → შემოწმებაზე → დაბრუნებული → დასრულებული / გაუქმებული
- **ღილაკები** დავალებაზე: მიღება, დაწყება, შემოწმებაზე გაგზავნა, დადასტურება, დაბრუნება, შეჩერება, განახლება, ვადის გადაწევის მოთხოვნა, გაუქმება
- **მთავარი პასუხისმგებელი** და **შემმოწმებელი** (ნაგულისხმევად — ვინც დავალება შექმნა)
- **ვადის გადაწევა**: თანამშრომელი ითხოვს ახალ ვადას მიზეზით, შემმოწმებელი ადასტურებს/უარყოფს; თავდაპირველი ვადა ინახება. ვადას პირდაპირ ცვლის მხოლოდ შემმოწმებელი
- **დასრულება და გაუქმება** მხოლოდ შემმოწმებელს ან პროექტის მენეჯერს შეუძლია
- **მიზეზები**: დაბრუნება, შეჩერება (+ განახლების თარიღი), გაუქმება — ინახება და ჩანს ისტორიაში
- **მტკიცებულება**: თუ მონიშნულია, შემოწმებაზე გაგზავნა ფაილის გარეშე არ შეიძლება
- **შეხსენებები** (ყოველ საათში): ვადამდე 24 სთ — შემსრულებლებს; ვადაგადაცილება — შემმოწმებელს
- **ანგარიშებისთვის**: დასრულების თარიღი, დროულად შესრულდა / თავდაპირველ ვადაში შესრულდა, გადაწევებისა და დაბრუნებების რაოდენობა
- **შაბლონები**: „მარაგების დათვლა“, „მარაგის შევსების მოთხოვნა“

## მოდული `steelhouse_hr` (დაყენებულია, ვერსია 19.0.1.21.2)

დამოკიდებულება: `hr`, `hr_org_chart`, `web_hierarchy`, `hr_holidays`, `mail`.

რას ამატებს:
- დეპარტამენტზე **„ხელმძღვანელები“** (`manager_ids`) — რამდენიმე თანაბარი ხელმძღვანელი; Odoo-ს ერთი `manager_id` დამალულია და ავტომატურად ივსება სიის პირველით (საჭიროა თანამშრომლის `parent_id`-სთვის). **„შემცვლელი“** (`deputy_id`), **„ხელმძღვანელის პოზიცია“** (`sh_head_title`, ჩანს „ვაკანტური: …“-ით, როცა ხელმძღვანელი არ ჰყავს)
- თანამშრომელზე: **„ხელმძღვანელი“** (`sh_manager_ids`, ყველა თანაბარი ხელმძღვანელი — ფორმაში და სიაში მენეჯერის ნაცვლად), **„დამატებითი პოზიციები“** (`sh_extra_job_ids` — მეორე როლი სხვა დეპარტამენტში), ფილტრი **„ჩემი გუნდი“** ყველა თანაბარი ხელმძღვანელისთვის (`sh_my_team`; `hr.employee` და `hr.employee.public`)
- **ორგანიზაციული სქემა** თანამშრომლის ბარათზე (`controllers/org_chart.py` — `hr_org_chart`-ის კონტროლერის გადატვირთვა + შაბლონი `static/src/org_chart`): თანაბარი ხელმძღვანელები გვერდიგვერდ, ქვეშევრდომები და რაოდენობები ყველასთვის ერთნაირად
- **შვებულების მოთხოვნაზე ცხრილი „შემცვლელები“** (`steelhouse.leave.delegation`: დეპარტამენტი + შემცვლელი; მოთხოვნა 1.6). ხელმძღვანელს (მათ შორის თანაბარს) წინასწარ ევსება მის დეპარტამენტებზე; შემცვლელებს ეგზავნება შეტყობინება დამტკიცებისას/გაუქმებისას
- **დეპარტამენტების იერარქიის ხედი** (`js_class="steelhouse_department_hierarchy"`, `web.assets_backend_lazy`): კომპანიის ბარათი ცენტრშია; „გაშლისას“ ბარათის ქვეშ მუქ ჩარჩოში ჩანს დეპარტამენტის **პოზიციები** (`hr.job`, ქვეშ — ვინ იკავებს ან „ვაკანტური“) და ქვედეპარტამენტები; ჩარჩო გვერდის ცენტრშია (ჩადგმულიც), ისარი მიუთითებს გაშლილ ბარათზე; ჩადგმული ჩარჩო საჭიროებისას აფართოებს გარეს. ბარათზე რიცხვი = ყველა, ვინც ხელმძღვანელების ქვეშაა ქვედეპარტამენტების ჩათვლით (`sh_headcount`, დაჭერით — სია)
- **თანამშრომლების ორგანიზაციული სქემა** (`js_class="steelhouse_employee_hierarchy"`, `hr.employee` და `hr.employee.public`, `views/hr_employee_hierarchy_views.xml`): იგივე განლაგება — ზემოთ ორი დირექტორი გვერდიგვერდ, „გაშლისას“ ადამიანის გუნდი ჩარჩოში გვერდის ცენტრში. დეპარტამენტის სტილები (სათაურის გადატანა, ჭრა) მხოლოდ დეპარტამენტებზეა, რომ თანამშრომლის ფოტო არ მოიჭრას
- **უშუალო ხელმძღვანელი ავტომატურად** (`hr.employee._sh_structure_manager`): სტრუქტურის წესით — უახლოესი ერთეულის პირველი ხელმძღვანელი; ივსება შექმნისას, დეპარტამენტის შეცვლისას და დეპარტამენტის ხელმძღვანელების/ზემდგომის შეცვლისას (ხელით მითითებული შექმნისას რჩება)
- **პოზიციის არჩევა**: ჩამოსაშლელ სიაში პოზიციას ერთეული ეწერება („ასისტენტი (ბადეების საწარმო / კომერციული მიმართულება)“, კონტექსტი `sh_job_department`); სიაში მხოლოდ თანამშრომლის დეპარტამენტის და ქვედანაყოფების პოზიციები; ქვედანაყოფის პოზიციის არჩევისას დეპარტამენტი იქ გადადის
- ახალი დეპარტამენტი ნაგულისხმევად „ფოლადის სახლის“ ქვეშ იქმნება (ზედა ცალკე დონე აღარ ჩნდება)
- თანამშრომლის და დეპარტამენტის ფორმა ინახება **მხოლოდ „შენახვით“** (ავტოშენახვა გამორთულია, როგორც შვებულებაზე)

- **შვებულება:** შემცვლელი იძებნება მთელ კომპანიაში, სახელით ან დეპარტამენტის სახელით (კონტექსტი `sh_search_department`); სტრიქონის დეპარტამენტი ავტომატურად სწორდება, ჩანს „შემცვლელის დეპარტამენტი“. შემცვლელის შეტყობინება მიდის ელფოსტით და Odoo-ს ჩატშიც (OdooBot). შვებულების ფორმა ავტომატურად აღარ ინახება (გვერდის დახურვა/ჩანართის შეცვლა — `static/src/leave_no_autosave`). შვებულების მთავარ გვერდზე ბარათი **„ჩემთან დასამტკიცებელი“** (`hr.leave.sh_waiting_for_me_count`, მხოლოდ დამმტკიცებლებს)
- **შემცვლელები (19.0.1.17–19):** ჩამოსაშლელ სიაში ჯერ სტრიქონის დეპარტამენტის თანამშრომლები, აკრეფით — მთელი ბაზა (`name_search`, კონტექსტი `sh_deputy_department_id`); შემცვლელი, რომელიც იმავე დღეებში თვითონ შვებულებაშია (დამტკიცებული ან დასამტკიცებელი, ნებისმიერი ტიპი), არ შეინახება — გაფრთხილება არჩევისას და შეცდომა შენახვისას; თარიღების შეცვლისასაც მოწმდება
- **შვებულების ფორმა:** მოთხოვნა მთელ სიგანეზე, „დამტკიცებული შვებულებების“ ბლოკი (`hr_leave_stats`) დამალულია; დიალოგი ფართოა, შემცვლელების ცხრილის სვეტები ფიქსირებული სიგანის, სახელები გადადის ახალ ხაზზე (`static/src/leave_dialog`)
- **აქტივობების მენიუ (⏰):** „შვებულების“ ქვეშ ჩანს ვისია, სტატუსი (დასამტკიცებელი / მეორე დამტკიცება), ტიპი და თარიღები (`res.users._get_activity_groups` + `static/src/activity_menu`)
- **კალენდარი:** შაბათ-კვირა და უქმეები ნაცრისფრად (კონტრაქტის თარიღის გარეშე — თანამშრომლის სამუშაო გრაფიკიდან, `hr.employee._get_unusual_days`); უქმეები — ღია მწვანე, „პირობით აღნიშვნებში“ „უქმე დღე“; შვებულებები ტიპის მკვეთრი ფერით (`static/src/time_off_dashboard/public_holidays.*`, `time_off_calendar.scss`)
- **დღეების ნაშთი** (`steelhouse.leave.balance`, SQL view, მიმდინარე წელი): ყველა ტიპი — გამოყოფილი / გამოყენებული / დასამტკიცებელი / დარჩენილი; მენიუ „ჩემი შვებულება → დღეების ნაშთი“ (საკუთარი) და HR-ისთვის „მენეჯმენტი → თანამშრომლების ნაშთი“ (ჩანაწერის წესები: საკუთარი / შვებულების ოფიცერი — ყველა). სხვა ქვეყნის ლოკალიზაციის ტიპები გამოტოვებულია
- **მენიუს სახელები** (ქართულად, `deploy/reload_ka.py` MENU_FIXES): „ჩემი შვებულება“ (იყო „ჩემი დრო“), „კალენდარი“ („დაფა“), „ჩემი მოთხოვნები“, „დღეების ნაშთი“; თანამშრომლებში „თანამშრომლების სია“
- **შეტყობინებები:** მომხმარებელზე არჩევანი „ელფოსტით / Odoo-ში / ორივე“ (`sh_notification_channel`; „ორივე“ = Odoo-ს inbox + `sh_notify_email_too`, `mail.thread._notify_thread_by_email` გადატვირთვით). Push შეტყობინებების მოთხოვნა HTTP-ზე დამალულია (`static/src/push_prompt`)
